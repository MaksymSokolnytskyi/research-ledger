# Закритий бета-тест research-ledger

Дякую, що тестуєш! Тут усе, що потрібно: встановлення за 10 хвилин, що саме перевіряти
і як повідомляти про проблеми.

## Що це за штука, коротко

Ledger робить з папки нотаток або проєкту **базу знань, якій можна довіряти**:

- кожне число в нотатках має мати джерело (запис прогону, лог, скрипт, URL), а аудит
  рахує ті, що не мають;
- провалені команди в Claude Code записуються автоматично (ключі й паролі маскуються),
  і коли ти виправив помилку, пишеш урок: `ledger lesson <id> "одним рядком"`. Наступного
  разу Claude побачить цей урок **перед** тим, як запустити ту саму команду;
- до твоїх промптів у Claude Code додаються відповідні нотатки й відомі провали;
- якість може лише рости: `ledger audit` порівнює показники з базовою лінією.

**Нічого не йде в мережу.** Усе працює локально. Відгук надсилаєш лише ти сам.

## Встановлення

Репозиторій поки приватний, тож потрібен доступ (запрошення від Максима) і вхід у
GitHub на твоєму компʼютері: `gh auth login` або звичайний git credential manager.

1. Пакет (Python 3.11+):

   ```bash
   pip install "git+https://github.com/MaksymSokolnytskyi/research-ledger"
   ledger --version
   ```

   Якщо `ledger` не знаходиться: на Windows папка `Scripts` твого Python має бути в
   PATH. Альтернатива без цієї проблеми: `pipx install "git+https://..."` або
   `uv tool install "git+https://..."`.

2. Плагін у Claude Code:

   ```
   /plugin install research-ledger --marketplace MaksymSokolnytskyi/research-ledger
   ```

   Плагін нічого не робить у папках без `ledger.toml`, тож його можна ставити для всіх
   проєктів. Якщо `ledger` не в PATH, на старті сесії Claude скаже про це сам.

3. Підключи свій проєкт або vault (нічого не перезаписує, спершу подивись план):

   ```bash
   cd мій-проєкт
   ledger init . --existing --dry-run           # що буде створено
   ledger init . --existing --language uk       # усе ledger-ове піде в папку ledger/
   ledger init . --existing --docs docs notes   # читати лише ці папки
   ```

   Поточний стан стає базовою лінією: старі проблеми не блокують, нові видно окремо.
   Додай `.ledger/` у `.gitignore` (це стан машини, а не нотатки).

4. `ledger audit` і відкрий `ledger/_generated/_health.md` в Obsidian.

Нова порожня база: `ledger init my-research --language uk` (без `--existing`).

## Що перевіряти (тиждень звичайної роботи)

- **Встановлення:** скільки часу зайняло, де застряг.
- **Шум:** чи заважає контекст, який ledger додає до промптів? Якщо так, у
  `ledger.toml` постав `inject = "named"` (лише коли промпт називає сутність з vault)
  і скажи, чи стало краще.
- **Помилки:** чи записувались провали, які не є помилками? `ledger failures` покаже
  список.
- **Корисний момент:** чи був випадок, коли Claude побачив урок або потрібну нотатку
  вчасно? Це найцінніше, що можна повідомити.
- **Швидкість:** чи помітна затримка перед відповіддю? `ledger stats` покаже цифри.

## Як повідомити

Найпростіше: скажи Claude Code «відправ фідбек про ledger: ...». Скіл
`/research-ledger:feedback` збере звіт, покаже його тобі і відправить лише після твого «так».

Або в терміналі:

```bash
ledger feedback --kind bug -m "що сталося"       # або --kind idea / --kind comment
```

Команда покаже звіт (версії, кількості, статистику хуків, без вмісту нотаток) і дасть
посилання на готовий issue. З `--submit` створить issue через твій `gh`.

Ще можна напряму: https://github.com/MaksymSokolnytskyi/research-ledger/issues/new/choose

## Відомі обмеження (не треба повідомляти, вже знаємо)

- **Сайти документації (mkdocs тощо)** будують навігацію поза нотатками, тож майже
  кожна сторінка виглядає «сиротою». Це стає частиною базової лінії й не заважає.
- **Пошук чисел без джерела** — евристика: дати, роки й версії пропускаються, але
  щось на кшталт «Python 3.11» у тексті може порахуватися.
- **Лічильники повторних провалів** живуть у `.ledger/` на кожній машині окремо;
  самі записи провалів і уроків синхронізуються разом з vault.
- **Перша сесія після встановлення** будує індекс: на кількох тисячах нотаток це
  кілька секунд один раз, далі близько 0.3 с на промпт.

## Як вимкнути

| що | як |
|---|---|
| усе в Claude Code | `/plugin disable research-ledger` |
| лише контекст у промптах | `ledger.toml`: `[context] inject = "off"` |
| лише запис провалів | `ledger.toml`: `[capture] enabled = false` |
| прибрати з проєкту | видалити `ledger.toml`, `ledger/` і `.ledger/` |
